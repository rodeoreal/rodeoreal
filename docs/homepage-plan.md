## 4. 페이지별 구성

### 4-1. 홈 `/`

1. 헤더: 상호, 메뉴, 전화 버튼(010)
2. 소개 문구 (사실만): "화정동 중심상업지구 상가·사무실 임대·매매" / "화정동에서 20년 넘게 상가·사무실 중개를 해왔습니다."
3. 빠른 검색: 거래유형(임대/매매), 층(지하/1층/2층/3층 이상), 면적대, 보증금·월세 상한 → `/listings?…`로 이동
4. 빠른거래 매물 최대 6건 (급매·무권리·양도양수 태그) + "전체 보기"
5. 최근 등록 매물 최대 6건
6. 조건 등록 안내 박스: "맞는 매물이 없으면 조건을 남겨 주세요" → `/request`
7. 사무소 정보 + 지도 + 연락처
8. 푸터 (6장 법정 표시사항 포함)

### 4-2. 매물 목록 `/listings`

- 필터: 거래유형(임대/매매), 태그(급매/무권리/양도양수), 층, 실면적(평) 범위, 보증금 상한, 월세 상한, 권리금(무권리만), 매매가 상한, 입점 가능 업종
- 정렬: 최신 갱신순(기본), 월세 낮은순, 보증금 낮은순, 면적 넓은순
- 필터 상태는 URL 쿼리로 유지 (공유·뒤로가기 대응)
- 카드 그리드: 모바일 1열, 태블릿 2열, 데스크톱 3열
- 결과 0건: "조건에 맞는 매물이 지금은 없습니다. 조건을 남겨 주시면 맞는 매물이 나올 때 연락드립니다." + 현재 필터값을 채운 채로 `/request` 이동
- 상단에 "최종 갱신일 YYYY-MM-DD" 표시

### 4-3. 매물 상세 `/listings/{id}`

1. 사진 갤러리 (없으면 "사진 준비 중" 자리표시)
2. 매물번호, 태그, 제목(예: "화정동 ○○빌딩 1층 상가 임대")
3. 가격 블록: 임대 = 보증금 / 월세 / 권리금 / 관리비, 매매 = 매매가 / 현 보증금 / 현 월세 / 수익률
4. 기본 정보 표: 5-1의 필수 표시항목 전부
5. 설명: 현재 업종, 입점 가능 업종, 특이사항(사실만)
6. 위치: 동·건물명 수준 지도 (호수 비공개)
7. 문의 블록: "매물번호 R-0123 으로 문의해 주세요" + [전화] [카카오 상담] [번호 복사]
8. 비슷한 매물 3건 (같은 거래유형·층·면적대)
9. 계약완료 매물은 상세 접근 시 "거래가 완료된 매물입니다" + 비슷한 매물로 안내 (목록에서는 제외)

### 4-4. 빠른거래 `/quick`

- 기존 랜딩 문구 유지: "빠른 거래가 가능한 화정동 상가 모음" / "급매, 무권리, 양도양수 추천 매물만 골랐습니다. 조건이 맞으면 바로 현장을 안내해 드립니다."
- 탭: 전체 / 급매 / 무권리 / 양도양수
- 기존 netlify 주소는 이 페이지로 연결 (10장 결정 사항)

### 4-5. 조건 등록 `/request`

- 기존 랜딩 폼 항목·문구를 그대로 이전한다 (1-1의 4번).
- 추가: 거래유형(임대/매매/둘 다), 매매일 때 매매가 상한
- 목록 화면에서 넘어온 경우 필터값 자동 입력
- 제출 후: "접수되었습니다. 조건에 맞는 매물이 나오면 연락드리겠습니다." + 카카오·전화 버튼
- 개인정보 동의 문구·보유기간(1년)은 기존 내용 유지

### 4-6. 사무소 소개 `/about`

- 상호, 대표, 등록번호, 주소, 전화 2종, 카카오
- 업무 분야: 화정동 중심상업지구 상가·사무실 임대·매매
- 경력: "20년 넘게" (Bro 확인 문구 외 추가 금지)
- 지도(주소 기준) + 영업시간(확인 필요) + 주차 안내(확인 필요)
- 블로그 링크: sanggalab.tistory.com

### 4-7. 개인정보 처리방침 `/privacy`

- 기존 문서 이전. 호스팅 업체가 바뀌면 "4. 제3자 제공 및 처리 위탁" 항목의 서버 정보를 실제 업체로 수정하고 시행일을 갱신한다.

### 5-4. 표기 규칙

- "입주 가능"이 아니라 "입점 가능"으로 쓴다.
- 과장 표현(대박, 최고, 압도적, 특급, 황금상권 등) 금지. 사실 수치만 쓴다.
- 확인되지 않은 정보(유동인구, 매출 등)는 쓰지 않는다. 값이 없으면 항목을 숨기거나 "문의"로 표시한다.

## 6. 법정 표시사항

중개대상물 표시·광고 관련 공인중개사법 규정에 맞춰 아래를 반영한다. 구현 전에 최신 고시 기준으로 항목을 한 번 더 확인한다.

- 모든 페이지 푸터: 중개사무소 명칭, 소재지, 연락처, 등록번호, 개업공인중개사 성명
- 매물 상세: 소재지, 면적, 가격, 중개대상물 종류, 거래 형태, 총 층수, 사용승인일, 입주가능일(화면 표기는 "입점 가능일"), 방향, 주차대수, 관리비
- 계약완료 매물은 목록에서 즉시 내린다 (허위·미끼 매물 방지).

### 7-1. 채널

| 채널 | 동작 | 노출 위치 |
|---|---|---|
| 휴대폰 010-8981-0202 | `tel:01089810202` | 헤더, 카드, 상세, 하단 고정 바, 푸터 |
| 사무소 031-938-5555 | `tel:0319385555` | 상세 문의 블록, 소개, 푸터 |
| 카카오 상담 | `http://pf.kakao.com/_aiXNs/chat` 새 창 | 헤더, 카드, 상세, 하단 고정 바, 푸터 |
| 조건 등록 폼 | `/request` | 홈, 목록 0건, 하단 고정 바 |

### 7-2. 흐름

1. 매물을 보고 문의: 카드/상세 → [전화] 또는 [카카오 상담]. 카카오는 메시지 자동 입력이 안 되므로, 버튼을 누르면 "매물번호 R-0123 복사됨" 알림 후 채팅창을 연다.
2. 맞는 매물이 없을 때: 목록 0건 또는 홈 안내 → `/request` (필터값 자동 입력) → 접수 완료 → 카카오·전화 버튼
3. 데스크톱: `tel:` 링크 옆에 번호를 텍스트로 함께 표시 (PC에서는 전화 연결이 안 됨)

### 7-3. 측정

- 클릭 이벤트: `call_mobile`, `call_office`, `kakao_chat`, `request_submit` (매물번호·페이지 경로 포함)
- 유입 경로(utm, referrer)는 폼 접수 시 함께 저장 (기존 처리방침에 명시된 자동수집 항목과 동일)

## 8. 데이터·기술 구성 (★ 기본안)

- ★ 정적 사이트 + 매물 데이터 파일 1개(`data/listings.json`)
  - 매물 갱신 = JSON 수정 후 배포. 주 1회 갱신(기존 랜딩 운영 주기)과 맞음
  - 빌드 도구 없이 HTML/CSS/JS로 작성, 또는 Astro 같은 정적 생성기로 매물별 상세 페이지 생성 (SEO 유리)
- 폼 접수: 기존 랜딩과 같은 방식(Netlify Forms 추정, 확인 필요) 유지
- 이미지: 매물당 최대 10장, 가로 1600px 이하 WebP로 변환, 지연 로딩
- 반응형 기준: 360px 모바일 우선
- SEO: 페이지별 title/description, 매물 상세는 `RealEstateListing` 구조화 데이터, sitemap.xml, 네이버 서치어드바이저 등록
- 관리자 도구(현 저장소)와의 연결은 2차. 1차는 공개용 JSON을 수동으로 만든다.

## 9. 작업 순서 (Claude Code 지시용)

1. 저장소 구조 결정에 따라 공개 사이트 폴더 생성 (10-1 기본값: 새 폴더 `site/`)
2. `data/listings.json` 스키마(5-1)와 샘플 3건 작성. 샘플은 명확히 "샘플" 표시
3. 공통 레이아웃: 헤더, 메뉴, 푸터(0장·6장 정보), 모바일 하단 고정 바
4. `/listings` 목록 + 필터 + 정렬 + URL 쿼리 유지
5. `/listings/{id}` 상세 + 문의 블록 + 매물번호 복사
6. `/quick` 탭 페이지 (기존 랜딩 문구 유지)
7. `/request` 폼 이전 (기존 항목·동의 문구 그대로 + 거래유형, 매매가 상한)
8. `/about`, `/privacy`, `/404`
9. 클릭 이벤트·SEO 메타·sitemap
10. 모바일(360px)·데스크톱 확인, 전화·카카오 링크 실제 동작 확인
