- 확인된 문제 (구현 전에 처리 필요)
  - `js/*.js`, `css/common.css` 전체 줄 앞에 줄번호(`  1<TAB>`)가 붙어 있어 스크립트·스타일이 동작하지 않는 상태다. 붙여넣기 과정에서 생긴 것으로 보인다.

## 4. 페이지별 구성

### 4-1. 홈 `/`

1. 헤더: 상호, 메뉴, 전화 버튼(010)
2. 소개 문구 (사실만): "화정역 상가·점포 임대·매매, 양도·양수 중개" / "2005년부터 화정동 중심상업지에서 상가를 중개해 왔습니다." + "1시간 30분 무료 주차" 한 줄
3. 빠른 검색: 거래유형(임대/매매), 층(지하/1층/2층/3층 이상), 면적대, 보증금·월세 상한 → `/listings?…`로 이동
4. 빠른거래 매물 최대 6건 (급매·무권리·양도양수 태그) + "전체 보기"
5. 최근 등록 매물 최대 6건
6. 조건 등록 안내 박스: "맞는 매물이 없으면 조건을 남겨 주세요" → `/request`
7. 사무소 정보 + 지도 + 연락처
8. 푸터 (6장 법정 표시사항 포함)

### 4-2. 매물 목록 `/listings`

- 필터: 거래유형(임대/매매), 태그(급매/무권리/양도양수), 층, 실면적(평) 범위, 보증금 상한, 월세 상한, 권리금(무권리만), 매매가 상한, 입점 가능 업종
- 정렬: 최신 갱신순(기본), 월세 낮은순, 보증금 낮은순, 면적 넓은순
- 필터 상태는 URL 쿼리로 유지 (공유·뒤로가기 대응)
- 카드 그리드: 모바일 1열, 태블릿 2열, 데스크톱 3열
- 결과 0건: "조건에 맞는 매물이 지금은 없습니다. 조건을 남겨 주시면 맞는 매물이 나올 때 연락드립니다." + 현재 필터값을 채운 채로 `/request` 이동
- 상단에 "최종 갱신일 YYYY-MM-DD" 표시

### 4-3. 매물 상세 `/listings/{id}`

1. 사진 갤러리 (없으면 "사진 준비 중" 자리표시)
2. 매물번호, 태그, 제목(예: "화정동 ○○빌딩 1층 상가 임대")
3. 가격 블록: 임대 = 보증금 / 월세 / 권리금 / 관리비, 매매 = 매매가 / 현 보증금 / 현 월세 / 수익률
4. 기본 정보 표: 5-1의 필수 표시항목 전부
5. 설명: 현재 업종, 입점 가능 업종, 특이사항(사실만)
6. 위치: 동·건물명 수준 지도 (호수 비공개)
7. 문의 블록: "매물번호 R-0123 으로 문의해 주세요" + [전화] [카카오 상담] [번호 복사]
8. 비슷한 매물 3건 (같은 거래유형·층·면적대)
9. 계약완료 매물은 상세 접근 시 "거래가 완료된 매물입니다" + 비슷한 매물로 안내 (목록에서는 제외)

### 4-4. 빠른거래 `/quick`

- 기존 랜딩 문구 유지: "빠른 거래가 가능한 화정동 상가 모음" / "급매, 무권리, 양도양수 추천 매물만 골랐습니다. 조건이 맞으면 바로 현장을 안내해 드립니다."
- 탭: 전체 / 급매 / 무권리 / 양도양수
- 기존 netlify 주소는 이 페이지로 연결 (10장 결정 사항)

### 4-5. 조건 등록 `/request`

- 기존 랜딩 폼 항목·문구를 그대로 이전한다 (1-1의 4번).
- 추가: 거래유형(임대/매매/둘 다), 매매일 때 매매가 상한
- 목록 화면에서 넘어온 경우 필터값 자동 입력
- 폼 위 안내 한 줄: "온라인에 올리지 않은 매물도 있습니다. 조건을 남겨 주시면 함께 찾아 드립니다." (플레이스 소개글의 비공개 매물 보유 내용을 담백하게 옮긴 것)

### 5-3. 카드 레이아웃

```
┌──────────────────────────────┐
│ [사진]          [급매][무권리] │
│ R-0123 · 임대 · 상가          │
│ ○○빌딩 1층                   │
│ 보증금 3,000 / 월세 200       │
│ 권리금 무권리                 │
│ 실면적 15평(49.6㎡) · 1층     │
│ 현재 업종: 카페 · 입점 가능 즉시 │
│ 갱신 2026-10-20               │
│ [전화] [카카오 상담]          │
└──────────────────────────────┘
```

- 매매 카드: "매매가 8억 5,000 · 보증금 5,000 / 월세 300 · 수익률 4.5%"
- 금액 표기: 만원 단위, 1억 이상은 "8억 5,000"
- 면적: 평 우선, ㎡ 병기 (1평 = 3.3058㎡, 소수 1자리)

### 5-4. 표기 규칙

- "입주 가능"이 아니라 "입점 가능"으로 쓴다.
- 과장 표현(대박, 최고, 압도적, 특급, 황금상권 등) 금지. 사실 수치만 쓴다.
- 확인되지 않은 정보(유동인구, 매출 등)는 쓰지 않는다. 값이 없으면 항목을 숨기거나 "문의"로 표시한다.

2. 맞는 매물이 없을 때: 목록 0건 또는 홈 안내 → `/request` (필터값 자동 입력) → 접수 완료 → 카카오·전화 버튼
3. 데스크톱: `tel:` 링크 옆에 번호를 텍스트로 함께 표시 (PC에서는 전화 연결이 안 됨)

### 7-3. 측정

- 클릭 이벤트: `call_mobile`, `call_office`, `kakao_chat`, `request_submit` (매물번호·페이지 경로 포함)
- 유입 경로(utm, referrer)는 폼 접수 시 함께 저장 (기존 처리방침에 명시된 자동수집 항목과 동일)

## 10. 결정 사항

1. 저장 위치: **rodeoreal 저장소에 `site/` 폴더를 새로 추가** (★안 확정). 배포는 Netlify에서 이 저장소를 연결하고 배포 폴더를 `site/`로 지정한다. 저장소가 공개 상태이므로 `site/`에는 공개용 데이터만 넣는다
2. 주소: **sanggalab.com 사용** (확정)
   - 구입처 블루웹(domain.blueweb.co.kr). 다른 곳에 연결된 적 없는 새 도메인이라 충돌 없음
   - 연결 방법: 사이트를 Netlify에 올린 뒤 Netlify에 도메인 추가 → 블루웹 DNS에서 `@` A 레코드와 `www` CNAME 입력 → HTTPS 자동 발급. 단계별 안내는 `sanggalab-dns-guide.md`
   - 티스토리는 sanggalab.tistory.com 그대로 둔다
3. 직원용 도구: **sanga-lookup.onrender.com(상가 중개 관리) 사용** (확정, CSV 내보내기 있음)
   - 확인된 것: "상가건물 조회" 앱, 로그인("입장") 뒤에만 내용이 보임. 내부 기능·데이터는 로그인 없이 확인 불가
   - 이걸 쓰면 rodeoreal 저장소의 깨진 관리 도구는 복구하지 않는다
   - 확인 필요: 매물 데이터를 CSV 등으로 내보낼 수 있는지 (공개 매물 JSON을 만들 때 필요). Render 무료 요금제라면 한동안 접속이 없으면 첫 화면이 30초 이상 늦게 뜰 수 있다
4. 첫 공개 매물: 상가룩업 CSV → 구글시트로 받는다 (8-1)
5. 영업시간·주차: 확정(0장, 4-6). 사무소 사진: 분홍 간판 사진 반영
6. 소개 문구: 4-6에 작성 (네이버 플레이스 소개글·카카오채널·간판 기준, 과장 표현 제외)
